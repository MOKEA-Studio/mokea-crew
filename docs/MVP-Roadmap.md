# MOKEA Agent CLI 계획서

작성일: 2026-10-05  
상태: 초안  
작업명: MOKEA Crew (`mokea`)

## 제품 원칙

- **100% 로컬:** 작업 실행, 프로젝트 정보, 설정, 이력은 사용자 기기에서 처리한다.
- **백엔드 없음:** 계정, 원격 API 서버, 중앙 데이터베이스, 텔레메트리 수집 서버를 제품 운영에 요구하지 않는다. 에이전트 CLI 자체는 각 공급자의 서비스를 이용할 수 있다.
- **MIT 라이선스:** 소스 코드를 MIT License로 공개한다.
- **사용자 통제:** 에이전트의 권한과 기존 CLI 인증은 사용자가 설정한 상태를 따른다.

## 1. 목적

Codex CLI와 Claude Code를 로컬 코딩 에이전트로 실행하고 관리하는 터미널 도구를 만든다. 사용자는 하나의 작업을 에이전트에 맡기거나, 여러 에이전트에 나누어 맡기고 진행 상태와 결과를 한 화면에서 확인한다. 각 에이전트는 사용자의 기존 CLI 설치와 로그인 정보를 사용한다.

제품 방향은 Buzz의 에이전트 작업 공간에서 영감을 얻되, 첫 버전은 중앙 서비스 없이 로컬 프로젝트에서 에이전트 작업을 실행하고 추적하는 데 집중한다.

## 2. 목표와 성공 기준

- Codex와 Claude Code가 설치되어 있는지 확인하고, 선택한 에이전트로 작업을 실행한다.
- 에이전트별 상태, 실행 중인 출력, 종료 상태를 TUI와 비대화형 출력에서 확인한다.
- 같은 프로젝트를 여러 에이전트가 동시에 수정해 생기는 충돌을 줄인다.
- 실행 기록과 결과를 로컬에 보관하고, 완료된 변경 사항을 사용자가 검토할 수 있게 한다.
- 새 에이전트를 추가할 때 실행 관리 코드를 바꾸지 않고 어댑터를 추가할 수 있게 한다.

첫 MVP 완료 기준:

1. `mokea doctor`가 Rust 앱, Git, Codex CLI, Claude CLI의 설치 및 인증 상태를 확인한다.
2. `mokea run --agent codex "..."`와 Claude 대응 명령으로 로컬 작업을 실행할 수 있다.
3. TUI에서 에이전트를 시작하고, 상태와 스트리밍 출력을 확인하며, 실행을 취소할 수 있다.
4. `--agent all` 실행 시 에이전트별 별도 Git worktree에서 작업한다.
5. 작업 결과에 요약, 변경 파일, diff 확인 방법, 종료 상태가 포함된다.
6. 앱 종료 뒤에도 실행 이력을 다시 볼 수 있다.

## 3. 사용자와 주요 흐름

### 대화형 흐름

1. 사용자가 저장소 안에서 `mokea`를 실행한다.
2. 홈 화면에서 현재 프로젝트와 감지된 에이전트, 이전 실행을 확인한다.
3. 작업을 입력하고 Codex, Claude 또는 전체 에이전트를 선택한다.
4. 각 에이전트의 상태와 출력이 갱신된다.
5. 완료 후 에이전트별 결과와 변경 사항을 비교하고, 선택한 worktree를 검토한다.

### 스크립트 흐름

```sh
mokea doctor
mokea agents list
mokea run --agent codex "로그인 오류를 조사하고 수정해줘"
mokea run --agent all "이 API 설계를 검토하고 개선안을 제안해줘"
mokea runs list
mokea runs show <run-id>
mokea runs cancel <run-id>
```

`--json` 옵션을 제공해 CI나 다른 스크립트에서 안정적으로 사용할 수 있게 한다.

## 4. 기술 선택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | Rust | 단일 바이너리 배포, 프로세스 제어, 비동기 실행에 적합 |
| 비동기 런타임 | Tokio | 여러 에이전트 프로세스와 입출력 스트림 관리 |
| 명령행 인자 | clap | 하위 명령, 도움말, 셸 완성 지원 |
| TUI | ratatui + crossterm | 실행 상태와 로그를 터미널 화면에 표시 |
| 직렬화·설정 | serde + TOML | 프로젝트별 설정과 구조화된 실행 기록 |
| 로컬 이력 | SQLite | 작업·에이전트 상태·요약을 단일 사용자 로컬 데이터로 저장 |
| 에이전트 실행 | 프로세스 어댑터 | 기존 Codex·Claude CLI의 설치와 인증을 재사용 |
| 에이전트 간 통신 | 초기에는 오케스트레이터의 작업·결과 전달 | 별도 메시징 서버 없이 MVP를 단순하게 유지 |

초기 에이전트 실행은 Codex의 `codex exec`와 Claude Code의 비대화형 `claude -p`를 감싸는 방식으로 구현한다. ACP는 실행·이벤트·권한 처리가 실제 요구에 맞는지 확인한 뒤 후속 단계에서 도입 여부를 결정한다.

## 5. 제품 범위

### MVP 포함

- 로컬 프로젝트 감지 및 기본 설정
- Codex 및 Claude CLI 감지와 사전 점검
- 한 에이전트 실행과 여러 에이전트 실행
- 실행 상태: 대기, 준비 중, 실행 중, 완료, 실패, 취소
- 스트리밍 로그와 사용자 취소
- 에이전트별 실행 요약 및 Git diff 확인
- 프로젝트별 설정과 실행 이력 저장
- JSON 출력 모드와 `doctor` 명령
- 에이전트별 동시 실행 제한 설정

### MVP 제외

- 호스팅 서비스, 계정, 팀 서버, 릴레이
- 구독료·토큰 사용량의 정확한 통합 과금 추적
- 자체 LLM API 연결 및 모델 선택 UI
- 원격 에이전트 실행
- 사용자 승인 없이 자동 병합·커밋·푸시
- 사용자 데이터 클라우드 동기화
- 모바일·웹 UI

## 6. 실행 및 변경 격리

- 단일 에이전트 실행은 사용자가 현재 저장소에서 실행하도록 명시한 경우 현재 작업 트리를 사용할 수 있다.
- `--agent all`은 기본적으로 에이전트마다 별도의 Git worktree와 브랜치를 만든다.
- 기존에 변경된 파일이 있는 저장소에서는 실행 전에 현재 변경 사항을 감지해 보여준다. 이를 덮어쓰거나 자동으로 정리하지 않는다.
- 완료 후 에이전트가 만든 worktree와 diff를 보여준다. 기본 동작은 변경 사항을 원래 브랜치에 자동 적용하지 않는 것이다.
- 실행 취소 시 하위 프로세스에 종료 신호를 보내고, 종료 여부를 확인한다.
- CLI의 권한·샌드박스 설정은 각 에이전트의 기존 동작을 임의로 완화하지 않는다. 안전 수준을 높이는 선택지는 앱이 명시적으로 제공한다.

## 7. 아키텍처 초안

```text
CLI / TUI
   │
   ├── ProjectContext       저장소 경로, Git 상태, 프로젝트 설정
   ├── RunCoordinator       작업 분해, 큐, 동시 실행 제한, 취소
   ├── AgentAdapter         에이전트별 설치 확인, 실행 인자, 이벤트 변환
   │      ├── CodexAdapter  codex exec
   │      └── ClaudeAdapter claude -p
   ├── WorkspaceManager     worktree 생성, 상태 확인, 정리
   └── RunStore             SQLite 이력 + 로그 파일
```

어댑터는 공통 실행 요청, 상태 이벤트, 최종 결과 타입을 사용한다. 앱은 공급자별 원시 출력에 결합되지 않도록 각 CLI 응답을 공통 이벤트로 변환한다. 지원되지 않는 이벤트는 원문을 로그에 보존한다.

제안 디렉터리 구조:

```text
crates/
  mokea-cli/       바이너리, 명령행 인터페이스
  mokea-core/      작업·상태·결과 타입, 조정기
  mokea-agents/    Codex·Claude 및 향후 어댑터
  mokea-workspace/ Git 저장소와 worktree 관리
  mokea-store/     설정·SQLite·로그 저장
```

## 8. 단계별 개발 계획

### 0단계 — 사양과 실행 방식 확인

- MVP 명령과 실행 흐름을 확정한다.
- Codex와 Claude가 제공하는 현재 비대화형 실행 옵션 및 스트리밍 이벤트를 확인한다.
- 한 에이전트 실행과 여러 에이전트 실행의 격리 정책을 검토한다.
- 저장소 위치와 바이너리 이름을 확정한다.

**완료 조건:** 명령 목록, 설정 초안, 에이전트 어댑터 계약이 문서화되어 있다.

### 1단계 — 최소 실행기

- Rust workspace와 clap 명령을 만든다.
- `mokea doctor`, `mokea agents list`, `mokea run`을 구현한다.
- Codex·Claude 프로세스 실행, 표준 출력·오류 스트리밍, 종료 코드 수집을 구현한다.
- Ctrl-C 취소와 명확한 실행 오류를 제공한다.

**완료 조건:** TUI 없이 두 에이전트를 각각 실행하고 결과를 터미널과 JSON으로 확인할 수 있다.

### 2단계 — TUI와 로컬 이력

- ratatui 홈 화면, 에이전트 선택, 작업 입력을 구현한다.
- 실행 목록, 실시간 로그, 상태와 취소 동작을 구현한다.
- SQLite에 실행 메타데이터를 저장하고 로그 파일 경로를 연결한다.

**완료 조건:** 실행 중인 에이전트를 한 화면에서 관찰하고 완료된 실행을 다시 열 수 있다.

### 3단계 — 다중 에이전트와 격리

- 동시 실행 큐와 설정 가능한 실행 한도를 구현한다.
- 각 에이전트별 Git worktree와 브랜치를 생성한다.
- 실행 완료 후 변경 파일과 diff 요약을 제공한다.
- 실패·취소 시 부분 결과와 worktree 상태를 보존한다.

**완료 조건:** Codex와 Claude가 같은 요청을 별도 작업 공간에서 실행하고 결과를 충돌 없이 비교할 수 있다.

### 4단계 — 협업 흐름과 배포

- 한 에이전트의 결과를 다른 에이전트에게 검토 요청으로 전달한다.
- 검토 결과와 구현 결과를 연결된 실행 그래프로 표시한다.
- macOS용 설치와 업데이트 방법, 사용 문서, 예제 프로젝트를 제공한다.
- 실제 사용 결과를 바탕으로 ACP 지원과 추가 에이전트 우선순위를 결정한다.

**완료 조건:** 구현 → 검토 흐름이 재현 가능하고, 새 에이전트 어댑터를 추가하는 방법이 문서화되어 있다.

## 9. 기본 설정 초안

전역 설정은 사용자 설정 디렉터리에, 프로젝트 설정은 저장소의 `.mokea/config.toml`에 둔다. 비밀 키나 CLI 인증 데이터를 복사해 저장하지 않는다.

```toml
[runs]
max_parallel = 2
default_isolation = "worktree"
retain_completed_worktrees = true

[agents.codex]
enabled = true
command = "codex"

[agents.claude]
enabled = true
command = "claude"
```

명령어는 사용자의 `PATH`에서 찾으며, 필요 시 설정으로 실행 파일 경로를 지정한다. 인증 정보는 각 공급자 CLI의 기존 저장소에 둔다.

## 10. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| CLI 버전별 출력 형식 변경 | 어댑터에서 버전 점검, 원시 로그 보존, 구조화 출력이 없을 때 텍스트 fallback 제공 |
| 에이전트가 권한 확인을 기다려 멈춤 | 대기 상태와 마지막 출력 표시, 취소 제공, 비대화형 권한 한계를 사용자에게 표시 |
| 여러 에이전트가 같은 파일을 수정 | 기본 worktree 격리, 자동 병합 금지, diff 검토 화면 제공 |
| 큰 로그가 로컬 저장 공간을 차지 | 메타데이터와 로그 분리, 로그 보존 정책 설정 |
| 인증 또는 구독 상태를 감지하지 못함 | 민감 정보를 읽지 않고 CLI 실행 점검 결과만 표시 |
| 한 에이전트 결과를 다른 에이전트가 오해 | 전달 시 요청, 원본 요약, 관련 diff 경로를 구조화해 함께 전달 |

## 11. 초기 결정 사항

- **언어:** Rust
- **CLI 프레임워크:** clap
- **TUI 프레임워크:** ratatui + crossterm
- **비동기 실행:** Tokio
- **초기 에이전트:** Codex CLI, Claude Code CLI
- **초기 연동 방식:** 각 CLI의 비대화형 실행 모드 어댑터
- **동시 실행 안전장치:** 에이전트별 Git worktree
- **저장 방식:** SQLite + 로컬 로그 파일
- **후속 확장:** ACP 검토, Gemini CLI 등 추가 어댑터
